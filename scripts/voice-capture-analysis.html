III. Three Scenarios — Design Recommendations

A. Voice Notes About Podcasts & Books
Source: global menu or book page  ·  Pathway: process_voice_capture()

Intent: "I just heard/read this, found it interesting, want to retain it for years."

This pathway already creates knowledge_items and generates quiz questions per node. It's the closest to working correctly. However:

  • The Frederick II podcast (49 facts across 7 nodes) got 0 microlearning cards because sync=True mode skips ML creation
  • One quiz per node means 49 facts → 7 questions. The key_facts system varies across reviews, which is adequate
  • Consider generating questions that reference the learner's specific stated facts, not just curriculum descriptions

Recommendation: Fix the sync bug. Otherwise this pathway works. Every meaningful fact you voice-note about a podcast should generate at least one node-level quiz question.

B. Knowledge Elicitation (Free Recall)
Source: review screen, node-level  ·  Pathway: run_voice_elicitation()

Intent: "Test what I already know long-term about Plato / Stoicism / etc."

This is the pathway with the biggest gap. You stated 232 facts across 29 sessions, and none became quiz questions. The system updates your knowledge level and reschedules existing FSRS items, but never creates new ones.

The nuance you identified:

  • Correct facts you stated as long-term knowledge: Less urgent to quiz, but if FSRS works well, Easy answers push to ~28 days — no burden. Worth generating, especially for nodes that don't yet have knowledge_items.
  • Wrong facts stated confidently: Highest priority to quiz. The LLM already tags these as confidence: "wrong" but the code never reads the tag. Examples: you said 409 BC destruction was Akragas (it was Selinunte), and the Vespers was "planned" (it was spontaneous).
  • Missed facts: Currently become HIGH-priority ML cards. You prefer encountering these through reading, not quizzing.

Recommendation: Create knowledge_items with high initial stability for demonstrated facts. Use confidence_tagged to create correction quizzes for wrong facts. Stop or deprioritize ML cards from missed facts.

C. Gap Identification
Source: prerequisite expansion  ·  Pathway: fill_prerequisite_gaps()

Intent: "It's OK to know what I don't know, but I want to fill gaps by reading, not by being quizzed on things I haven't encountered."

Currently, gap-fill items are already well-deprioritized:

  • -5.0 score penalty (below all book-sourced items)
  • Capped at 3 per review batch
  • Only appear when node_knowledge != 'unknown'

The more concerning path is missed facts from elicitation becoming HIGH-priority ML cards (1:3 ratio), which effectively quizzes you on things you never read about.

Recommendation: Gap-fill items are fine as-is. The main fix is stopping or reframing missed-fact → ML cards from elicitation (see Scenario B).

IV. The confidence_tagged Discovery

Extracted Data That's Never Used

Both voice prompts (VOICE_ELICITATION_PROMPT and VOICE_CAPTURE_ANALYSIS_PROMPT) ask the LLM to tag every factual claim with a confidence level:

// From VOICE_ELICITATION_PROMPT, field #7: "CONFIDENCE_TAGGED": For each key claim the learner makes, tag their apparent confidence: "certain" — stated as fact "uncertain" — hedged, "I think...", "maybe..." "wrong" — stated confidently but incorrect

This data exists in every voice_transcripts.llm_result JSON blob. But no code ever reads confidence_tagged. A grep across the entire codebase shows zero references outside the prompt definitions.

Examples of "wrong" tags in your captures:

  • Akragas capture: You said "the city was destroyed by Carthage in 409 BC" — the LLM noted this was actually Selinunte's destruction date, not Akragas
  • Sicilian Vespers: You said it was "planned" — the LLM noted this is a common misconception; it was spontaneous (though possibly orchestrated by Aragonese agents)
  • Stoicism: You placed Stoicism's origin "around the time of Plato" — it started with Zeno of Citium c. 300 BC, a generation after Plato

Impact: These are exactly the misconceptions that should be corrected through targeted quiz questions. The extraction infrastructure is already built — it just needs to be wired up to quiz generation.

V. Five Issues & Recommended Fixes

1. Elicitations don't create quiz questions for captured facts

run_voice_elicitation() extracts facts and updates knowledge_states but never creates knowledge_items or calls generate_question(). Result: 29 sessions × ~8 facts = 232 facts sitting in JSON, never reviewed.

Impact: 47% of all voice-extracted knowledge has no quiz path.

Fix: After extracting captured facts, create knowledge_items for nodes where none exist yet (engaged/anchored level). Set initial FSRS stability to 14–28 days. For nodes that already have items, the existing FSRS reschedule handles it.
2. confidence_tagged "wrong" facts are extracted but never used

The LLM tags confidently-stated incorrect facts, but the code never reads this field. Wrong facts are the highest-value targets for correction quizzes.

Fix: Parse confidence_tagged from llm_result. For each "wrong" item, create a targeted ML card: "Correction: [wrong claim]. What's actually true?" with a new source_type 'correction' at HIGH priority.
3. Missed facts from elicitation become HIGH-priority quiz questions

After elicitation, the top missed fact triggers an ML card with query "Why is this important: [fact]" at 1:3 interleaving ratio. This quizzes you on things you haven't read about.

Fix: Remove the missed-fact → ML card creation from run_voice_elicitation() (lines 3775–3788). Missed facts stay as metadata in the elicitation results UI. Alternatively, lower priority from 'voice_wondering' (HIGH) to 'follow_up' (LOW, 1:7).
4. sync=True mode silently drops microlearning card creation

process_voice_capture() has if not sync: before ML card creation. The Frederick II podcast (49 facts, 18 wonderings) got 0 ML cards because it was reprocessed with sync=True.

Fix: Add a trigger_ml=True parameter that enables ML creation regardless of sync mode. Or trigger ML cards in a separate post-processing step.
5. 31 ML cards stuck in "pending" status

The April 6 batch (patron-client, Vespers, Greek sculpture, classical learning, etc.) never completed processing. These are mostly from the latest elicitation session.

Fix: Run a reprocessing script to trigger _run_microlearning_research() on all pending cards. Then investigate why they stalled (likely claude -p auth or rate limiting).
