The real problem isn’t growth — it’s the backlog

167 items due with only 25 ever reviewed. The system is generating knowledge faster than it’s being reinforced. Spaced repetition hasn’t truly started yet — almost everything is still in “first encounter” mode.

The Scheduling Problem

Screen time vs. book time

The stated goal: “I should not spend more time reading on my screen than reading actual books.” The app should reinforce knowledge acquired from books, podcasts, and documentaries — not become the primary learning channel.

This creates a clear priority hierarchy:

Card Type Priority Scheduling Rationale
SR due (knowledge items) HIGHEST Show first, unlimited Strengthens existing knowledge. Fast to answer (5–15 sec each).
Voice elicitation ML cards HIGH Interleave 1:3 with SR Unexpected discoveries from free recall. Limited volume (~3 per session).
First-encounter review cards MEDIUM After SR due items New topics need first exposure, but not at the cost of reinforcement.
Follow-up ML cards LOW 1 per 5–7 SR cards Curiosity-driven but time-consuming to read. Shouldn’t dominate.
Target: 20–30 SR reviews in 5 minutes

If the user has only a few minutes, spaced repetition should fill them entirely. ML cards (which require reading a paragraph) should only appear after the SR batch is done, or as a deliberate “explore” choice. The current interleaving ratio needs to shift heavily toward SR.

The Missing Mechanism

“I also want to know…”

During review, the user remembered where Cicero was assassinated but wanted a card for the year. There is currently no way to:

  • Flag a specific fact gap during review
  • Request a specific card be generated
  • Split a question into sub-questions (WHERE vs. WHEN vs. WHY)
Recommendation: “I also want to know…” input

After answering a question, show a subtle text input: “Something else you want to remember?” The user types “year Cicero assassinated” and this becomes a targeted ML card with high priority — it’s a specific, identified gap, not speculative exploration.

This also captures the “I knew this but want to know more” signal that is currently lost when the user taps “knew” on a card.

Recommendations

Priority order

  1. Scheduling rebalance — SR first, ML interleaved sparingly
    Show all due SR cards before any ML reading. Interleave voice-elicitation ML at 1:3 ratio with SR. Follow-up ML cards at 1:7. Target: 20–30 quick SR reviews in 5 minutes.
  2. “I also want to know…” input after review answers
    Capture specific knowledge gaps during review (the Cicero year problem). High-priority targeted ML cards from user-identified gaps.
  3. Daily review budget
    Cap total review time or card count per session. Ensure SR takes priority within budget. Show progress: “14/20 SR done, 2 ML cards today.”
  4. Voice elicitation ML cards get high priority
    Flag ML cards from voice sessions as high-signal. These are unexpected, edge-of-knowledge discoveries — more valuable than follow-up-triggered cards.
  5. Reading Echoes in article reader
    Wire book claim embeddings into reader margins. The #1 unfulfilled differentiator. Book connections pipeline already runs — needs UI only.
  6. Wire the resurfacing engine
    760 lines of working cross-book resurfacing code with zero integration points. 1–2 hours to wire endpoint + UI.
  7. Extract key_facts for all 9 curricula
    Currently only Sicily Greek (299 facts, 70 nodes). The “facts first” principle needs data across all 719 nodes.
